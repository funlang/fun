# package-demo

A minimal Fun project with a local path dependency. It shows the package
workflow without network access.

```text
package.fun                 # manifest; `resolved` is generated by tidy
src/main.fun                # bin; imports the dependency by package name
libs/hello/package.fun      # path dependency
libs/hello/lib.fun
```

`fun` below is the command-line binary (`fun.exe` on Windows). From the
repository root, after building, the in-tree binary is
`src/prj/fun/funcmd`; from this directory that is
`../../../src/prj/fun/funcmd`.

```text
cd fun/demos/package-demo

fun run
# run: package 'hello' is not installed; run 'fun package tidy'

fun package tidy
fun run
# hello, world

fun run Alice
# hello, Alice

fun src/main.fun Bob
# hello, Bob

fun pack -o dist/package-demo
dist/package-demo
# hello, world
```

`dist/package-demo.exe` is the Windows output. The packed program contains the
dependency library and runs without `~/.fun`.

Notes:

- `hello` is a path dependency (`source: 'libs/hello'`). `tidy` uses it in
  place; a git dependency would need `git` and an exact tag, branch, or commit.
- `tidy` also writes the resolved block in `package.fun`. For a path
  dependency it records this checkout's absolute path, so treat that block as
  local state rather than something to commit.
- `fun run` runs the manifest `bin` from the project root. `fun <script>` is
  the flat mode of the same launcher and runs any script with the project's
  dependencies available.
- Runs are read-only: missing or stale dependencies report
  `run 'fun package tidy'` instead of fetching anything.
  `FUN_PACKAGE_READY=1` skips project mode (for example with a broken
  manifest).
